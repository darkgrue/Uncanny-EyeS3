# Texture Pre-processing Optimizations Design

**Date:** 2026-05-26  
**Status:** Approved  
**Scope:** `geneye.py`, `eagle_*.eye`, `EyeRenderer.cpp`

---

## Problem

The eagle eye's sclera texture (256×128, 65 KB) cannot fit in DRAM alongside the
angle map (54 KB), radius map (54 KB), and iris texture (47 KB) — the combined 220 KB
exceeds the ~170 KB runtime DRAM budget. It falls back to PSRAM, causing severe cache
thrashing during render.

The root cause of the thrashing is a **stride mismatch** in the current texture layout.
The render loop accesses textures with radius changing ~0.79 steps/pixel and angle
changing ~0.55 steps/pixel. In the current row-major layout `T[radius * texW + angle]`,
radius steps jump 512 bytes between rows — well outside the 32-byte L1 cache line —
while angle steps are sequential (2-byte stride). Because radius changes *more often*
than angle, the dominant access pattern is cache-unfriendly.

Result: eagle eye renders in ~73 ms (texture overhead ~45 ms vs the 28 ms default-eye
baseline), yielding ~11 FPS.

---

## Solution: Two composable changes

### A. Transpose texture layout to angle-major

Change the in-memory layout from row-major `T[radius * texW + angle]` to column-major
`T[angle * texH + radius]`. Radius values for a given angle are now stored
consecutively (stride 2 bytes), converting the dominant access pattern from
cache-unfriendly (512-byte jumps) to sequential.

**Physical size is unchanged.** The `EyeTexture` struct fields `width` (angle count)
and `height` (radius count) retain their meaning.

**geneye.py change** — `convert_texture_to_rgb565`: iterate column-major instead of
row-major:

```python
# Before (row-major)
for y in range(h):
    for x in range(w):
        data.append(rgb565(pixels[x, y]))

# After (angle-major / column-major)
for x in range(w):
    for y in range(h):
        data.append(rgb565(pixels[x, y]))
```

**EyeRenderer.cpp change** — two texture lookup lines:

```cpp
// Before
color = irisTexData[texV * irisTexW + texU];
color = scleraTexData[texV * scleraTexW + texU];

// After
color = irisTexData[texU * irisTexH + texV];
color = scleraTexData[texU * scleraTexH + texV];
```

`texU * texH` peaks at 255 × 128 = 32,640 — fits in `int`, no overflow.

Generated header comment updates from `(WxH px, RGB565 polar map)` to
`(WxH px, RGB565 angle-major)` to make the layout explicit.

### B. Per-texture resolution cap in `.eye` config

Add optional `"maxTexW"` and `"maxTexH"` fields to each texture section in `.eye`
JSON. When present they override the global `MAX_TEX_W=256` / `MAX_TEX_H=128` caps
for that specific texture.

**`geneye.py` change** — `convert_texture_to_rgb565` gains `max_w` and `max_h`
parameters (defaulting to the existing globals). `_load_texture` reads `maxTexW` /
`maxTexH` from the config dict and passes them through.

**Eagle eye config change** — add to the sclera section of `eagle_466.eye` and
`eagle_480.eye`:

```json
"sclera": {
    "filename": "sclera.png",
    "maxTexW": 128,
    "maxTexH": 64,
    ...
}
```

This reduces the eagle sclera from 256×128 (65 KB) to 128×64 (16 KB).

**DRAM budget after change:**

| Cache component | Size |
|-----------------|------|
| Angle map       | 54 KB |
| Radius map      | 54 KB |
| Iris texture (256×92) | 47 KB |
| Sclera texture (128×64) | **16 KB** |
| **Total** | **171 KB** |

This just fits the ~170 KB DRAM budget. The `begin()` DRAM→PSRAM fallback already
exists; a marginal overrun degrades gracefully rather than crashing.

Sclera radial resolution changes from 0.9 px/texel to 1.8 px/texel. Acceptable for
the eagle sclera's large-stroke vein structure.

**DRAM budget warning** — `geneye.py` prints a warning after computing final texture
dimensions if the combined cache estimate for a given eye exceeds a configurable
threshold (default `DRAM_BUDGET_BYTES = 170 * 1024`). This makes future over-budget
eyes self-documenting at generation time.

## Build Notes

Generated eye headers from before this change use the old row-major layout and are
**incompatible** with the updated renderer lookup formula. The post-build script
(`gen_eyes_all.py`) regenerates all headers automatically on the next build, so a
normal build is sufficient. If headers were manually cached or the post-build script
is bypassed, run `python resources/tools/geneye.py -all` manually.

---

## Expected Outcome

With sclera in DRAM and angle-major layout:

| Eye | Render (estimated) | Transfer | FPS (estimated) |
|-----|--------------------|----------|-----------------|
| default | ~28 ms | ~20 ms | ~20 FPS (unchanged) |
| eagle | ~40–45 ms | ~20 ms | ~16–18 FPS |

The ~28–33 ms improvement in eagle render comes from eliminating PSRAM cache misses
on the sclera entirely, plus the access-pattern improvement from transposition also
benefiting the DRAM-resident iris and sclera caches.
